# Stage 18.31.1a: Fresh database startup repair

A clean database failed because migrations run before `main.py` calls `init_class_reset_sphere()`. Migration 044 creates item 504, but migration 046 requires both sphere items 501 and 504. The failure at 046 stops the ordered runner, so migration 049 never creates `location_travels`, and travel restart recovery later crashes. This patch adds ordered dependency migration `045a_seed_new_path_sphere_dependency.py`. It idempotently seeds item 501 before migrations 046-048 while leaving migration 049 as the sole owner of the travel table. The regression mirrors the real startup order without pre-seeding canonical items, uses an isolated temporary working directory, performs two complete initialization cycles, checks migrations 000-051, items 501/504, `location_travels`, quick_check, foreign keys, and second-start idempotency. Production database, WAL, and SHM files are not opened or modified by the patch validation.
